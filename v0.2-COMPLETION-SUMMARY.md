### Data Flow Sequence

```
1. User launches Desktop App
   ↓
2. main.ts spawns backend (NestJS)
   ↓
3. Backend initializes ConfigLoaderService
   ├─ Loads config from OS user data folder
   │  (~/Library/Application Support/TicketSystem on macOS)
   ├─ Initializes database (SQLite)
   └─ Starts listening on auto-detected port
   ↓
4. Desktop App creates BrowserWindow
   └─ Loads http://localhost:{PORT}
   ↓
5. Frontend loads (static export)
   ├─ Checks setup status via /api/v1/setup/status
   └─ Routes to Setup Wizard if not initialized
   ↓
6. User completes 4-step setup wizard
   ├─ Step 1: Selects data folder (via IPC)
   ├─ Step 2: Creates admin account
   ├─ Step 3: Reviews configuration
   └─ Step 4: Receives QR code with API URL + JWT
   ↓
7. POST /api/v1/setup/init
   ├─ Backend validates input
   ├─ Creates admin user in database
   ├─ Generates JWT token
   ├─ Saves config to disk
   └─ Returns success
   ↓
8. Frontend displays QR code containing:
   {
     "apiBase": "http://192.168.1.X:3000",
     "token": "eyJhbGciOiJIUzI1NiIs..."
   }
   ↓
9. User scans QR on iPhone
   ├─ QRCodeScanner captures data
   ├─ NetworkManager.processQRData() extracts URL + token
   ├─ KeychainManager saves token securely
   ├─ UserDefaults saves API URL
   └─ Tests connection with GET /api/v1/tickets
   ↓
10. iPhone displays connected status
    ├─ Downloads ticket list
    ├─ Refreshes every 30 seconds
    └─ Updates as changes occur
```

## 🎓 Key Learnings & Design Patterns

### Implemented Patterns
1. **Factory Pattern** - StorageService selects storage strategy
2. **Strategy Pattern** - IStorageStrategy for pluggable storages
3. **State Machine** - SetupWizard manages 4-step flow
4. **Adapter Pattern** - ConfigLoaderService adapts to OS differences
5. **Observer Pattern** - SwiftUI @Published properties
6. **Bridge Pattern** - Electron IPC for frontend-backend communication

### OS-Specific Handling
- **macOS:** ~/Library/Application Support/TicketSystem
- **Windows:** %APPDATA%\TicketSystem
- **Linux:** ~/.config/TicketSystem
- **iOS:** UserDefaults + Keychain

### Security Measures
- JWT token-based authentication
- iOS Keychain for token storage
- Electron IPC sandbox (no native modules in renderer)
- CORS properly configured
- Bearer token in API requests
- Config files encrypted path
